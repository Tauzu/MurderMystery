# NPC評価

NPC（AI）の品質を確認した記録。設計書 §8 に沿った実装を、実際のモデルで動かして評価する。

## 1. 評価の方法

`pnpm --filter @mm/server eval:npc [シナリオJSON] [--rounds=2] [--model=...] [--raw]`

- 全席をNPCにして、導入からカード公開・会話・投票・結果まで1ゲームを自動で進める。
- 会話は、各セットで全席が `--rounds` 回ずつ順に発言する（実ゲームの30〜60秒間隔ではなく、続けて呼ぶ）。
- `ANTHROPIC_API_KEY` が必要（`.env` から読む）。呼び出しの費用が発生する。
- 自動チェック：発言の長さ、メタ発言（AI・プロンプト等の語）、自分の状況文の丸写し、犯人の自白、他キャラの秘密（状況文・未公開カード）に12文字以上一致する発言。
- 自動チェックでは判定できない項目（矛盾、口調、自然さ）は、出力を読んで確認する。

## 2. 結果

### 2026-10-12 モデル `claude-haiku-5-5`、シナリオ「雪山荘の晩餐」、rounds=2

実行ログ：[NPC評価_実行ログ_2026-10-12.txt](NPC評価_実行ログ_2026-10-12.txt)

| 項目 | 結果 |
|---|---|
| 自動チェック | 問題なし（メタ発言、丸写し、自白、他人の秘密への酷似、文字数超過のいずれも検出されず） |
| フォールバック | 0件（形式不正・API失敗なし） |
| AI呼び出し | 40回、平均1.3秒 |
| 使用トークン | 約13万（2巡の評価。予算は1ゲーム30万） |
| 勝敗 | 探偵側の勝ち（犯人に3票） |

読んで確認した点：

- **口調**：全員が丁寧語で、立場に沿った落ち着いた話し方だった。キャラクターごとの口調の差は小さい（改善の余地あり）。
- **秘匿**：犯人役（医師）は、犯行を認めず、ラウンジで本を読んでいた・化粧室へ行ったと説明して疑いをそらした。非犯人は自分の見たことを根拠に医師を追及した。誰も、他の人しか知らないはずの内容を話していない。
- **矛盾**：犯人役が第3回で「化粧室へ行った」と話を変えたが、公開済みカードとは矛盾していない。非犯人は、ほかの人の発言（鍵の拾得場所、しおりの位置など）を引用して質問していた。
- **推理**：非犯人の3人全員が、公開された手がかりと発言のはぐらかしを根拠に犯人へ投票した。理由の記述も具体的だった。
- **課題**：評価では順番に発言させているため、質問に答えるやりとりが機械的に整いすぎている。実ゲームでは30〜60秒の間隔が入り、人間も混ざる。この点は実機で確認が必要。

| 問題 | 原因 | 対処 |
|---|---|---|
| 発言・投票の約半数が定型文・ランダムになった | モデルが既定で「思考」を行い、出力トークン上限（300）を使い切って本文が空になった | API呼び出しで思考を無効にした（`packages/npc/src/llm.ts`）。再評価でフォールバックは0件になった |

## 4. 勝敗バランスの測定

`pnpm --filter @mm/server eval:balance [シナリオJSON] [--games=6] [--rounds=2] [--parallel=2] [--no-persona]`

全席をNPCにした対戦を複数回行い、探偵側の勝率を出す。犯人に入れなかった探偵側の投票先と理由も表示する。1ゲームあたり約13〜15万トークン。

- **性格を付ける**：席ごとに性格（慎重、直感型、頑固、懐疑的、協調的）をランダムに与える。付けないと、NPCの探偵が毎回同じ結論に揃い、勝率が100%になって測定にならない（`--no-persona` で確認できる）。
- **レート制限**：同時に進めるゲーム数が多いと、APIの入力トークン制限（毎分50万）に当たる。測定では429を待って再試行し、同時実行は既定で2ゲームにしている。**最初の測定は、この429でAIの投票が最多名指しのフォールバックに置き換わっていた**ため、勝率が信頼できなかった。測定結果では「犯人に入れなかった」行に `[fallback]` が出ていないことを確認する。
- **精度**：1ゲームの結果は、AIの返答と性格の抽選で大きく揺れる。8ゲームでは±25%程度の幅があり、16ゲームでも±20%程度。勝率が0%や100%に張り付いていないかを見る粗い確認には使えるが、数%の違いを比べるには使えない。
- **妥当性**：性格は人間の意見の割れ方を想像で近づけたもの。人間のプレイで勝率がどうなるかは別に確認する必要がある。

### 2026-10-14 の結果（claude-haiku-5-5、性格あり、rounds=2）

| シナリオ | 探偵側の勝率 | 備考 |
|---|---|---|
| 001 雪山荘の晩餐（現行） | 7/16（44%） | |
| 002 嵐の船上（現行） | 9/16（56%） | |

調整の経緯（どちらも性格あり、フォールバックなしの測定）：

| シナリオ・版 | 探偵側の勝率 | 変更 |
|---|---|---|
| 001 改訂前（最初の版） | 6/6（100%）※性格なし | 犯人を直接示すカードが5枚前後 |
| 001 改訂1 | 2/8（25%） | 疑わしい人物を足し、犯人を指す手がかりを減らした |
| 001 改訂2 | 18/26（69%） | 麻衣のカードに「薬の匂い」（医師を連想させる手がかり）を足した（診察室の匂いと書いた版） |
| 001 改訂3（現行） | 7/16（44%） | 「診察室のような」を「薬のような」にして、連想を弱めた |
| 002 初版 | 6/8（75%） | 新規作成 |
| 002 改訂1 | 24/26（92%） | 巡回の証言を「遅れた」に弱めた |
| 002 改訂2 | 14/16（88%） | 通路が水浸しだった（誰の袖も濡れる）事実を犯人の手札に足した |
| 002 改訂3 | 13/16（81%） | 船長も帳簿の署名者とし、目撃者の様子を淡泊にした |
| 002 改訂4（現行） | 9/16（56%） | 須藤の目撃を「制服姿の誰か」の後ろ姿にして、顔を特定できなくした |

分かったこと：

- **1枚の手がかりで勝率が大きく動く**。001は「薬の匂い」の1文で25%から約70%に、002は目撃者が事務長と特定できるかどうかで80%台から50%台に動いた。特に、**犯人を名指しにできる目撃や物証**は、強すぎると勝敗がほぼ決まる。
- 改訂前の001の問題：探偵側に、犯人を直接示すカードが多すぎた（デキャンタの前の医師、患者記録の「白石医院」、戻ってきた鍵、ラウンジの空席、金属音）。犯人の手札に、自分を不利にするカードが2枚あり、3枚公開するルールでは必ず1枚を公開させられた。九条蓮の通話（20時30分〜21時30分）と、21時10分にラウンジへ行った証言が矛盾していた。

## 5. 未確認の事項

- 人間が混ざった実ゲームでの発言のタイミング・自然さ（実機で確認する）。
- 他のシナリオ、他のモデル（上位モデル）との比較。品質に不満が出た場合に行う。
- 1ゲームの費用。評価の約13万トークンは2巡の場合で、実ゲーム（会話時間600秒、30〜60秒間隔）では発言回数が増える。予算30万トークンで足りるかは、実プレイで確認する。
- プロンプトキャッシュ：現在のプロンプトは最小サイズに満たず、効いていない。履歴を含めた共通部分の分け方を、費用が問題になった時点で見直す。
